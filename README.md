# ViRAGE

**ViRAGE** — самостоятельный pipeline-проект для построения и анализа графиков по текстовому запросу и данным.

Название расшифровывается как **Visual RAG and Analysis Generation Engine**.

---

## Что делает проект

ViRAGE принимает:

- текстовый запрос пользователя;
- входные данные.

На выходе проект формирует:

- подготовленные данные;
- построенные графики;
- вычисленные численные показатели;
- структурированное описание графиков;
- итоговые выводы;
- верификацию выводов с указанием, на какие данные и элементы графика они опираются.

Проект не ограничивается построением графиков.  
Его цель — получить **графики + промежуточные вычисления + проверяемые выводы**.

---

## Ключевая особенность проекта

Главная особенность ViRAGE — использование **VisRAG**.

### Что это значит
В системе есть отдельный retrieval-слой, который ищет знания о том:

- какие графики подходят под конкретную задачу;
- как их лучше строить;
- какие ограничения и анти-паттерны нужно учитывать;
- какие решения чаще подходят для типовых и нетиповых случаев.

То есть ViRAGE не пытается строить график “вслепую” только по одному промпту.  
Сначала система получает знания о хороших практиках построения графиков, и только потом переходит к генерации.

---

## Для кого проект

ViRAGE подходит:

- аналитикам, которым нужно быстро получать графики и объяснимые выводы;
- исследователям, которым нужен воспроизводимый pipeline визуальной аналитики;
- разработчикам, которым нужен управляемый графовый workflow, а не один LLM-вызов;
- командам, которым важно не только построение графика, но и проверка, откуда взялся итоговый вывод.

---

## Зачем нужен проект

У существующих решений часто есть одна или несколько проблем:

- графики строятся без явного retrieval по знаниям о хорошей визуализации;
- запрос пользователя интерпретируется слишком свободно;
- кодогенерация идёт слишком рано;
- график строится, но не анализируется глубоко;
- итоговые выводы не имеют понятной доказательной опоры;
- отсутствует отдельный этап верификации.

ViRAGE проектируется так, чтобы закрыть эти проблемы.

## Общая архитектура

ViRAGE построен как **многошаговый pipeline**.

### Основные этапы

1. **Текстовый запрос**  
   Пользователь задаёт, что нужно сделать с данными и какие графики его интересуют.

2. **Query Understanding**  
   Система понимает цель запроса, ограничения и определяет тип случая:
   - `canonical`
   - `non-canonical`

3. **Planning**  
   Система строит план выполнения:
   - какие шаги нужны;
   - какие проверки нужны;
   - что строить в первую очередь.

4. **DataProfiler**  
   Формируется краткое описание структуры данных:
   - типы полей;
   - пропуски;
   - числовые и категориальные столбцы;
   - временные поля;
   - заметки о качестве данных.

5. **Data Preparation**  
   Данные приводятся в рабочее состояние:
   - очистка;
   - нормализация;
   - обработка пропусков;
   - базовые исправления структуры.

6. **VisRAG**  
   Система извлекает знания о подходящих графиках и правилах их построения.

7. **Code Generation**  
   Формируется код для построения графиков и расчёта нужных чисел.

8. **Code Run**  
   Код исполняется, графики строятся, вычисления сохраняются.

9. **Artifact Store**  
   Сохраняются артефакты:
   - код;
   - графики;
   - подготовленные данные;
   - вычисленные показатели;
   - промежуточные результаты.

10. **Chart Reading**  
    Построенный график читается как структурированный объект.

11. **Fact Extraction**  
    Из графика и численных результатов извлекаются наблюдаемые факты.

12. **Reasoning**  
    На основе фактов формируются содержательные выводы.

13. **Verification**  
    Каждый вывод проверяется и связывается с основанием:
    - данными;
    - графиком;
    - вычислениями;
    - артефактами.

## Алгоритм работы от начала до конца

### Шаг 1. Пользователь задаёт запрос
Пример:
> Покажи динамику продаж по месяцам и объясни, где есть рост и спад.

### Шаг 2. Система понимает задачу
ViRAGE определяет:
- что хочет пользователь;
- какой тип графика вероятнее всего подойдёт;
- требуется ли стандартный или более сложный режим работы.

### Шаг 3. Система анализирует данные
Пайплайн определяет:
- какие поля пригодны для анализа;
- есть ли временные данные;
- есть ли числовые показатели;
- есть ли проблемы качества данных.

### Шаг 4. Система готовит данные
Перед построением графика данные очищаются и приводятся к рабочему виду.

### Шаг 5. Включается VisRAG
Retrieval-слой ищет знания о том:
- какие графики лучше строить;
- какие правила качества нужно учесть;
- какие ошибки нужно избегать.

### Шаг 6. Генерируется код
Генерируется код для:
- построения графика;
- вычисления числовых показателей;
- сохранения промежуточных результатов.

### Шаг 7. Код исполняется
Система:
- строит графики;
- сохраняет результаты;
- фиксирует артефакты выполнения.

### Шаг 8. График читается обратно
ViRAGE не останавливается на картинке.  
После построения график снова переводится в структурированное представление.

### Шаг 9. Извлекаются факты
Примеры фактов:
- минимум;
- максимум;
- тренд;
- изменение по интервалам;
- сравнение серий.

### Шаг 10. Формируются выводы
Система строит итоговые тезисы на основе:
- данных;
- графика;
- вычисленных значений.

### Шаг 11. Выводы верифицируются
Для каждого вывода система старается показать:
- на какие элементы графика он опирается;
- на какие вычисления он опирается;
- какие артефакты подтверждают вывод.

---

## Почему архитектура такая

ViRAGE специально построен как **разделённый pipeline**, а не как “один умный агент”.

Это даёт:

- лучшую управляемость;
- лучшую воспроизводимость;
- понятные контракты между шагами;
- более простое тестирование;
- возможность отдельно улучшать каждый модуль;
- меньший риск галлюцинаций.

---

## Чем проект отличается от простых text-to-chart решений

Обычный упрощённый сценарий выглядит так:

`запрос -> LLM -> график`

ViRAGE работает иначе:

`запрос -> понимание -> планирование -> профиль данных -> подготовка данных -> VisRAG -> генерация кода -> исполнение -> чтение графика -> факты -> выводы -> верификация`

Это длиннее, но значительно надёжнее и объяснимее.

---

## Текущий технический подход

Проект строится вокруг следующих принципов:

- orchestration верхнего уровня через **LangGraph**;
- использование **LangChain** в LLM-зависимых шагах;
- хранение промежуточных артефактов;
- типизированное состояние pipeline;
- разделение стандартных и нестандартных сценариев;
- опора на retrieval по знаниям о графиках.

---

## Что особенно важно в проекте

### 1. VisRAG — это отдельный слой
Retrieval не встроен внутрь одного промпта.  
Это самостоятельный этап pipeline.

### 2. График — не финальная точка
После построения график снова анализируется как структура, а не только как изображение.

### 3. Выводы должны быть проверяемыми
Итоговая цель — не просто “красивый график”, а график с понятным, проверяемым выводом.

### 4. Промежуточные состояния сохраняются
Подготовленные данные, код, графики и вычисления — это полноценные артефакты, которые можно анализировать отдельно.

---

## Кратко

**ViRAGE** — это retrieval-guided pipeline визуальной аналитики.

Он:
- понимает запрос;
- анализирует данные;
- использует знания о хороших графиках;
- строит графики через управляемый процесс;
- читает построенные графики обратно;
- извлекает факты;
- формирует выводы;
- проверяет, на чём эти выводы основаны.

Именно это делает его не просто генератором графиков, а системой **объяснимой визуальной аналитики**.
