# ViRAGE

**ViRAGE** — система построения и анализа графиков по текстовому запросу и табличным данным.

Название расшифровывается как **Visual RAG and Analysis Generation Engine**.

## Назначение проекта

Система принимает:

- текстовый запрос пользователя;
- файл с табличными данными.

В результате работы формируются:

- описание запроса и его аналитической цели;
- описание структуры данных;
- подготовленный набор данных;
- набор кандидатов на визуализацию;
- итоговая спецификация **Vega-Lite**;
- построенный график;
- аналитические выводы по изображению графика;
- сведения о качестве результата и промежуточные артефакты.

Проект предназначен не только для построения графика. Его основная цель — получить **корректную визуализацию, понятные промежуточные результаты и проверяемые выводы**.

## Основная идея

Система работает по схеме **«поиск подходящего решения → формирование спецификации → проверка → построение графика → анализ результата»**.

ViRAGE не формирует программный код для построения графика. В проекте используется **спецификация Vega-Lite** как основной промежуточный артефакт. Это позволяет:

- формально проверять корректность результата;
- ограничивать систему поддерживаемым подмножеством операций;
- сохранять полную историю промежуточных шагов;
- сравнивать результаты по формальным метрикам.

## Ключевые особенности

### 1. Отдельный этап подбора подходящей визуализации

В проекте есть самостоятельный слой **VisRAG**. Он подбирает подходящие варианты визуализации и правила их построения с учётом:

- запроса пользователя;
- структуры данных;
- реально доступных полей после подготовки данных.

### 2. Жёсткое сопоставление с данными

Система не принимает найденный вариант без проверки. На этапе анализа запроса и на этапе выбора визуализации проверяется:

- какие столбцы действительно есть в данных;
- какие столбцы были исключены при подготовке;
- какие поля являются идентификаторами и не должны использоваться как основные аналитические оси без явного основания.

### 3. Построение через спецификацию, а не через программный код

График строится на основании **валидированной спецификации Vega-Lite**. Это упрощает проверку результата и делает процесс более устойчивым.

### 4. Анализ выполняется по изображению графика

После построения график передаётся на этап визуального анализа. Выводы формируются по изображению и журналу промежуточных шагов, а не путём прямого чтения исходной таблицы на завершающем этапе.

### 5. Полная трассировка выполнения

Система сохраняет:

- промежуточные артефакты;
- журналы шагов;
- обращения к моделям;
- сведения о числе использованных токенов.

Это упрощает проверку результата, отладку и сравнение с другими решениями.

## Общая архитектура

Актуальная версия проекта построена как последовательный вычислительный конвейер со следующими этапами:

1. **Query Understanding** — определение цели запроса, требуемых операций и аналитической задачи.
2. **Data Profiler** — описание структуры таблицы, типов полей, качества данных и идентификаторов.
3. **Request Analyzer** — сопоставление элементов запроса с реальными столбцами таблицы.
4. **Data Preparation** — подготовка данных с учётом аналитической задачи.
5. **VisRAG** — подбор и ранжирование кандидатов на визуализацию.
6. **Planning** — формирование правил выполнения, проверки и анализа.
7. **Chart Generator** — построение спецификации Vega-Lite.
8. **Spec Validator** — проверка корректности спецификации.
9. **VegaLite Plot Drawing** — построение графика по валидированной спецификации.
10. **Scenegraph Check** — техническая проверка результата построения.
11. **Empty Chart Check** — обнаружение пустого или бессодержательного графика.
12. **Spec Score** — оценка качества спецификации.
13. **VLM Analysis** — анализ изображения графика.
14. **Fact Extractor** — выделение наблюдаемых фактов.
15. **Reasoner** — формирование интерпретаций и выводов.
16. **Verifier** — проверка выводов на внутреннюю согласованность.
17. **Insights** — подготовка итогового ответа пользователю.
18. **Vision Score** — оценка качества изображения графика.
19. **Evaluation Summary** — сводная оценка результата.

## Логика работы от начала до конца

### Шаг 1. Приём запроса и данных

Пользователь передаёт запрос и файл с таблицей.

### Шаг 2. Определение задачи

Система определяет:

- что именно требуется от визуализации;
- какой тип анализа нужен;
- какие ограничения уже содержатся в запросе.

### Шаг 3. Анализ структуры данных

Выявляются:

- числовые поля;
- категориальные поля;
- временные поля;
- идентификаторы;
- признаки, которые могут повлиять на корректность визуализации.

### Шаг 4. Сопоставление запроса со столбцами таблицы

Система определяет, каким столбцам соответствуют слова и выражения из запроса, и фиксирует неоднозначности.

### Шаг 5. Подготовка данных

Данные приводятся к рабочему состоянию. При этом подготовка зависит от задачи. Например, для задач распределения классов сохраняется кратность строк, потому что именно она задаёт частоты.

### Шаг 6. Подбор подходящей визуализации

VisRAG выбирает подходящие варианты визуализации с учётом реальных столбцов и ограничений задачи.

### Шаг 7. Формирование спецификации Vega-Lite

Система строит спецификацию, ограниченную поддерживаемым подмножеством Vega-Lite.

### Шаг 8. Проверка спецификации

Спецификация проверяется на корректность. Ошибки фиксируются в артефактах выполнения.

### Шаг 9. Построение графика

На основании валидированной спецификации строится график и сохраняются технические артефакты построения.

### Шаг 10. Проверка результата построения

Система проверяет:

- был ли график действительно построен;
- содержит ли он визуальные элементы;
- не является ли он пустым или бессодержательным.

### Шаг 11. Анализ изображения

Изображение графика передаётся на этап анализа. Далее выделяются факты, формируются выводы и выполняется их проверка.

### Шаг 12. Формирование итогового ответа

Пользователь получает:

- построенный график;
- выводы;
- журналы промежуточных шагов;
- при необходимости — сводку метрик и артефактов.

## Состав проекта

Основные части проекта расположены в каталоге `src`.

### `src/application`

Содержит прикладной уровень:

- настройки проекта;
- загрузку конфигурации;
- запуск конвейера;
- контракты входа и выхода.

### `src/domain`

Содержит доменные модели, перечисления и типизированные структуры данных.

### `src/graph`

Содержит описание последовательности шагов конвейера.

### `src/infrastructure`

Содержит рабочий контекст выполнения, сохранение артефактов и технические вспомогательные механизмы.

### `src/llm`

Содержит фабрику моделей и вспомогательные функции для работы с моделями.

### `src/services`

Содержит основные шаги обработки запроса и данных.

## Конфигурация и окружение

Настройка проекта разделена на две части.

### Конфигурация проекта

Файл `ui/config/project.toml` задаёт:

- режим работы;
- используемые модели для разных ролей;
- параметры построения графиков;
- параметры расчёта метрик.

### Переменные окружения

Файл `.env` используется для:

- ключей доступа к внешним сервисам;
- параметров трассировки;
- параметров наблюдаемости.

Ключи доступа не должны храниться в файле конфигурации проекта.

## Пользовательский интерфейс

Для ручной работы предусмотрен интерфейс на **Streamlit**.

Он позволяет:

- загрузить файл с таблицей;
- ввести запрос;
- наблюдать промежуточные этапы выполнения;
- просматривать обращения к моделям;
- видеть число использованных токенов;
- получать итоговый график и аналитические выводы.

## Метрики и проверка качества

В проекте предусмотрены следующие основные оценки:

- качество спецификации;
- качество изображения графика;
- наличие пустого результата;
- качество итоговых выводов;
- суммарная сводка выполнения.

Эти данные предназначены как для внутренней проверки, так и для сравнения с другими решениями.

## Для кого подходит проект

Проект может быть полезен:

- аналитикам;
- исследователям;
- разработчикам систем визуальной аналитики;
- командам, которым требуется проверяемый и воспроизводимый процесс построения графиков.

## Краткое резюме

ViRAGE — это система управляемого построения и анализа графиков, в которой:

- запрос разбирается поэтапно;
- визуализация подбирается с учётом данных;
- график строится через спецификацию Vega-Lite;
- результат проходит проверку;
- выводы формируются на основании изображения и промежуточных артефактов;
- все значимые этапы сохраняются и могут быть проверены отдельно.
